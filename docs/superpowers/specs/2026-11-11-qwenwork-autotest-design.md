# 千问办公自动化测试平台：规格与设计

日期：2026-11-11。阶段：需求与设计已获用户批准，实施中。

## 1. 目标与范围

建立本机单用户 Web 测试平台，导入 CSV 后驱动已登录的千问办公桌面 App，固定分批执行样本，采集可观测的任务过程，生成单次测试报告。界面采用 React、TypeScript 和 Ant Design，中文交互。

自动化采用 Playwright Electron/CDP，辅助只读访问本地任务事件。不使用 macOS Accessibility，不修改 App 安装包、不写入 App 数据库。跨平台设计覆盖 macOS/Windows，本次真实验收环境为 macOS，Windows 未实测时必须明确标注。

本期不含回答质量评分、其他模型、多人远程服务、自动登录、附件文件内容归档、隐藏系统提示词或服务端不可见推理过程采集。生成附件可保留 App 暴露的引用与元数据。

## 2. 已确认需求

### R01 CSV 导入与模板

- 固定四列：`ID,Prompt,专家套件ID,模型类型`。UTF-8，支持 BOM、标准 CSV 引号、逗号和引号内换行。
- ID、Prompt 必填；ID 在单个文件内唯一。ID 按字符串处理，保留前导零；Prompt 保留实际内容及换行，不静默改写。
- 每行最多一个专家套件ID，可以为空，空值表示不引用专家套件。
- 模型仅支持“标准”“高级”；空值默认“标准”。其他值、重复ID、缺列或格式错误在导入时拦截，展示行号与原因，不自动提交部分有效行。
- 上传入口旁提供“下载 CSV 模板”超链接，模板包含四列表头及无专家套件的示例行。示例 ID 是测试样本ID，不伪造真实专家套件ID。
- 导入预览展示全部待执行内容、总样本数与执行配置；用户点击开始后才创建运行。

### R02 固定分批调度

- 默认并发为 2，正整数可配置。按 CSV 顺序切为固定批次，最后一批可不足并发数。
- 一批任务均结束（成功或重试耗尽失败）后才进入下一批，不使用滑动窗口补位。
- 当前批次内各样本独立重试；没有失败的样本不陪同重跑。人工处理中的样本仍属于当前批次并阻止下一批启动。
- 默认批次间隔 10 秒，可配置；首批前、末批后不额外等待。
- “并发”指 App 中同时处于执行中的任务。共享窗口的模型选择、专家套件选择、输入及提交操作需要串行互斥，避免不同样本的输入交叉；提交后任务应能在后台并发执行。
- 本期一次只允许一个测试运行占用执行器，避免多个运行叠加超过设定并发。

### R03 失败与重试

- N 是额外重试次数，默认 N=2，可配置，总尝试次数最多 N+1。
- App 明确失败、限频、确认停止后的超时按重试规则处理；每次新建独立 App 任务，复用同一样本的 Prompt、专家套件和模型配置。
- 每次尝试记录实际 App 任务ID，不覆盖旧ID。首次尝试的重试序号为 0。
- 重试耗尽标记样本失败并继续后续队列，不把失败样本当成未执行样本丢弃。
- 单次尝试执行超时默认 10 分钟，可配置。超时先请求停止原任务，只有确认停止后才允许新建任务重试。
- 第 k 次额外重试的默认等待为 `min(10 + 5 × (k-1), 60)` 秒，即 10、15、20…60 秒；参数可配置。
- 限频优先遵循 App/服务端明确给出的等待时间：实际提交时间不得早于本地退避和服务端等待两者的较晚截止时间。
- 限频阻止后续新提交（包括重试、同批尚未提交项及后续批次），已经运行的任务继续；仍需满足原批次完成屏障。
- 无法确定提交是否成功、无法确认停止、任务关联丢失等情况进入“待人工核对”，暂停该批次的新提交，不因连接错误盲目创建重复任务。
- 不存在或不可用的专家套件、不可选的模型必须明确显示，不允许静默降级为无套件或其他模型。启动前可检测的配置错误直接拦截。

### R04 追问与人工处理

- `userAskQuestion` 有可用选项时，每道题自动选择第一项并提交；多选题也仅选第一项。
- 多题追问逐题应用此规则；选项取界面/事件的原始顺序，不按字母重新排序。
- 保存问题、选项、自动回答和时间。追问去重，避免刷新或重放事件导致重复回答。
- 必须自由输入、无可用选项，或文件/工具等权限确认转人工处理。人工在 App 中完成，平台提供任务定位及恢复跟踪入口。
- 其他已运行任务继续，本批等待该任务结束。
- 人工等待期间暂停该任务的 10 分钟执行超时计时；样本总耗时仍包含人工等待，单列人工等待时长。

### R05 成功判定和采集

- 成功以 App 明确且能关联到当前尝试的成功终止状态为准；回复文本静止、页面无动画或数据库暂时不更新都不能单独证明成功。
- 任务失败、取消、停止、限频与连接中断必须分别建模，不能把停止事件当成成功。
- 每次尝试至少关联平台运行ID、CSV 样本ID、尝试ID、App chat/task ID；App 暴露时同时保留 subChat/session/turn/input/message ID。
- 保存实际提交用户消息及引用信息、请求与实际模型、专家套件ID、最终回复、错误分类与原文、重试序号、各阶段时间和耗时。
- “最终输入”指实际提交并能从 App 确认的消息内容及引用信息，不包含 App 未暴露的系统提示词，也不通过给 Prompt 注入隐藏标记来关联任务。
- 保存本平台任务的可观测事件：输入接收、回复、工具调用与结果、追问与回答、状态、错误和终止。每条记录包含来源、原始事件标识（如有）、接收时间及规范化类型；允许关联的原始有效载荷留作排查。
- 仅采集本平台创建并准确关联的测试任务，不导出其他历史会话；不记录认证令牌、Cookie 或密钥。
- 采集状态显示“完整/部分/不可用”及缺失原因。界面应说明这里的完整仅相对已验证的 App 可观测事件，不承诺服务端内部全链路。

### R06 时间与指标

- 每次尝试记录提交开始、App 接收、最终成功/失败/停止、人工等待等时间。执行器使用单调时钟计算存活期间耗时，另保存 UTC 时间戳用于跨进程恢复与展示。
- 样本总耗时：首次提交到最终结果，含提交后的重试退避、限频等待及人工等待，不含首次提交前排队。另列每次尝试耗时、排队和人工等待时长。
- 平均耗时：最终成功样本的样本总耗时之和 ÷ 最终成功样本数；无成功样本显示“—”。失败样本耗时单独展示。
- 一次成功率：首次尝试成功的样本数 ÷ 本次有效样本总数。
- 总体成功率：最终成功样本数 ÷ 本次有效样本总数。
- 本次有效样本总数在开始时固定为成功导入并纳入本次运行的行数；重试不增加分母。失败与用户停止造成的未完成项不计为成功，分别展示数量。测试中途停止时报告显著标识“已停止/未全部完成”，不伪装成完整验收报告。
- 零样本禁止启动；零分母指标展示“—”，不显示 NaN 或 Infinity。指标以未四舍五入数据计算，百分比展示保留两位小数。

### R07 本地持久化、恢复与控制

- 开始、尝试创建意图、提交阶段变化、App 关联、事件及终止结果实时持久化。App 操作与数据库事务之间不能假设原子性；提交中的崩溃必须进入核对流程。
- 平台重启或 App 重连先核对已知原任务：能确认则继续跟踪，不能确认则标记待人工核对，不自动重复提交。
- 暂停提交：停止产生新的提交；已运行任务继续，退避截止时间保留。
- 继续：仅在连接健康且无待核对阻塞时恢复调度。
- 停止测试：取消未提交样本及未发起的重试，对运行中任务请求停止。未确认停止的任务保留待核对标记，不虚报停止成功。
- App 连接丢失时暂停新提交；连接恢复后先补采事件并核对状态。
- 本地服务只绑定回环地址，不提供远程访问。变更操作校验请求来源；不把 App 调试端口暴露到局域网。

### R08 报告与导出

- 页面保留运行历史、配置快照、运行进度、样本表、尝试明细和事件时间线。
- 概览展示样本数、成功/失败/未完成数、平均耗时、一次成功率、总体成功率；展示限频次数、人工等待和采集缺失提示。
- CSV 明细包含样本和尝试关联、实际输入、模型/套件、状态、重试与耗时等；JSON 包含运行、样本、尝试和事件；HTML 是可独立打开的单次汇总报告。
- CSV 采用标准转义并处理表格软件公式执行风险，JSON 保留原始文本；HTML 对所有 Prompt、回复与事件内容进行转义。
- 上传旁的模板超链接和三个导出入口均需验证实际下载内容，不仅检查按钮存在。

## 3. 技术方案选择

推荐混合适配：Playwright/CDP 驱动 App 中真实界面交互，结合界面状态及只读本地持久事件确认任务归属和终止。它能覆盖实际选择模型/套件与提交路径，并减少页面切换引起的观测丢失；代价是需要按 App 版本维护适配和验证事件格式。

备选一是纯 CDP 界面驱动，只看当前页面。依赖更少，但后台任务的工具链与状态可能不可见，不能满足采集要求时不作为本项目默认方案。

备选二是直接调用内部业务 IPC/API。与 UI 相比耦合更深，鉴权、参数与语义尚未确认；不采用提取凭据或绕过授权的方式，也不以未经验证的接口替代真实 App 工作流。

## 4. 组件、数据与接口边界

技术栈：Node.js/TypeScript 本地执行服务，Fastify HTTP/SSE，SQLite 平台自有数据库；React/Vite/Ant Design 前端；Playwright 控制及测试；Vitest 验证调度与指标。依赖版本在实施时锁定并保留锁文件。

| 组件 | 职责 | 主要边界 |
| --- | --- | --- |
| CSV 导入 | 解码、验证、预览、模板 | 产出不可变样本清单，不启动任务 |
| 运行服务 | 配置快照、操作、查询与导出 | HTTP 命令与 SSE 状态订阅 |
| 批次执行器 | 批次屏障、并发、重试、退避、暂停/停止 | 只依赖适配器事件，不直接读 DOM |
| App 适配器 | 连接、界面互斥、选择模型/套件、提交、停止、回答、定位 | 返回实际任务关联和规范化状态 |
| 只读事件采集 | 关联任务的持久事件读取、解码、游标、去重 | 不写 App DB，不把未知事件映射成成功 |
| 平台存储 | 运行、样本、尝试、事件、恢复检查点 | 自有 SQLite 事务与唯一约束 |
| 报告服务 | 指标、明细、HTML/CSV/JSON | 只读平台数据，不触发 App 操作 |

核心记录为 `runs`、`samples`、`attempts`、`events`、`human_interventions`。App 数据库路径及程序路径通过 macOS/Windows 路径解析与用户配置确定，不硬编码本机用户名。只读 App DB 连接使用 SQLite 正确读取已提交 WAL 数据；不以 immutable 模式忽略活动 WAL，也不使用损坏的一次性主文件复制。

适配器能力检查覆盖：连接状态、App 版本、模型选择、套件引用、提交/任务关联、后台运行、终止识别、停止确认、追问处理和事件覆盖。未通过关键能力检查不得启用真实运行；模拟模式仅供平台调度/UI 验证，必须醒目标注且不能作为真实 App 验收依据。

2026-11-11 用户追加确认：业务验收使用“查一下我店铺名 / 查一下我今天订单 / 查一下我今天收入 / 查一下我昨天的差评”，标准模型并发 4。已验证左侧任务 DOM 的 `data-chat-id` 与 `data-status` 可监听，采用 MutationObserver 通过 CDP binding 推送状态、唤醒执行器并记录事件；终态仍与消息记录交叉确认。断线/页面重载/虚拟列表未渲染时依靠持久化记录轮询补偿，不能仅凭 idle/unseen 判成功。

建议项目结构：`apps/web`（页面）、`apps/server`（HTTP/启动）、`packages/core`（调度/指标/类型）、`packages/qwen-adapter`（桌面接入）、`packages/storage`（持久化）、`tests`（集成与端到端）、`docs/superpowers`（规格/计划/验证证据）。

## 5. 状态与恢复规则

- 样本：排队 → 提交中 → 运行中 → 成功；运行中 → 失败 → 等待重试 → 提交中；失败且无剩余重试 → 最终失败。
- 人工追问进入等待人工；未知提交/未知停止/关联丢失进入待核对。两者均有明确操作入口，且不等于任务失败或成功。
- 平台停止使未提交项变为取消；运行中的最终状态需 App 确认。运行汇总区分完成、暂停、等待人工、待核对、停止中、已停止。
- 每次提交前写入尝试意图，确认实际任务后再保存关联。进程在二者之间退出时，恢复不能跳过核对而重试。
- 事件以 App 原始ID加关联维度去重；无稳定原始ID时使用已验证的游标组合，去重方式写入适配器验收证据。终态事件幂等，重复事件不重复计时、重试或计数。

## 6. 页面流程

1. 连接检查：App 路径、连接健康、已验证能力及当前版本；需要启用调试或重启 App 时提前显示原因与操作状态，不强行退出有活动任务的 App。
2. 新建测试：上传与模板超链接、错误提示、数据预览、并发/重试/超时/间隔配置、开始。
3. 运行详情：进度和指标、当前批次、样本状态表、暂停/继续/停止；点击样本查看 App ID、输入、回复、尝试、追问、错误与事件。
4. 人工处理：显示原因与关联 App 任务；用户在 App 完成处理后，平台重新核对并继续跟踪。
5. 历史与报告：筛选运行、查看完整/中止状态、下载 CSV/JSON/HTML。

## 7. 分阶段交付与技术门槛

### G0：桌面接入证据

在当前安装版本验证 Electron/CDP 能否连接；不修改安装包。验证选择标准/高级、引用真实可用专家套件、提交并取得精确任务关联、跨页面继续采集、辨别成功/失败/停止、解析事件。验证两个任务可在后台同时运行。

同时验证能否触发并处理 `userAskQuestion`、停止任务并确认终止。需要真实套件时先从 App 可用清单读取；没有可用套件或不能稳定触发特定场景必须记录为尚未验收，不能虚构成功结果。

允许安全启动带回环调试参数的 App；已有 App 未完成任务不能被直接强制退出。若当前 App 必须重启才能开启接入，先检查活动状态并展示处理方式。认证与业务限制不得通过修改 App、伪造签名或提取令牌规避。

G0 不能证明的关键能力需返回事实与证据，再确认方案调整；不把未验证的方法写成已经可用的生产适配。

### G1：可测试执行核心

持久化、CSV、固定分批、退避、限频、超时、追问、恢复、指标和导出。用可控适配器测试时序与故障，避免依赖真实服务限频或人为制造线上故障。

### G2：完整本地平台

Ant Design 界面、操作和下载入口；生产构建由本地服务提供，开发模式单独配置。启动方法、路径覆盖、数据位置与故障诊断写入 README。

### G3：本地验收

启动本地服务，浏览器验证上传/下载/控制/报告；少量真实 App 任务核对提交、并发、输入、模型/套件及最终报告。产生真实模型用量已获用户同意。自动测试、真实成功与未覆盖项分别记录。
